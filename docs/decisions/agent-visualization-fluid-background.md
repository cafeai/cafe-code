## Context and alternatives

The supplied template uses an actual WebGL fluid simulation, not a polar-wave
fragment shader. Its advection, curl/vorticity, pressure solve, splats, shading,
electric cyan-to-magenta palette and virtual orbit produce the requested ink-like
motion. Copying only its colours does not reproduce that effect.

The supplied engine carries Pavel Dobryakov's MIT notice. Preserve the full
notice with the adapted code and its embedded copies. The reviewed template's
SHA-256 is `e67688917b113eff12c54425e5a903e54e96a2512cb2f326c1c92f94b6b572ac`.
It is a user-supplied implementation input, never a runtime read of a user's
Downloads directory. No remote runtime/font, smooth-scroll module, hero, form,
photo or marketing copy is adopted.

Sending the complete engine in every provider tool description would duplicate
code in model context and encourage approximate rewrites. A new network/resource
API or privileged bridge is unnecessary. Select one fixed bundled in-document
library, made available only to generated documents and used through an exact
decorative canvas marker. Existing saved HTML without that marker is unchanged
visually; immutable source/posters are never rewritten.

## Decision

- Vendor the actual supplied solver/shader equations, shading, colour generation
  and orbit/splat treatment. Keep changes explicit: finite sizing/work/lifecycle,
  transparent local presentation and removal of unused bloom/noise machinery.
  The template already disables bloom; do not allocate its unused resources.
- The generated-document wrapper embeds the fixed library before received
  source under the existing inline-script CSP. One `canvas[data-cafe-fluid]`
  opts into that library. Canonical preview/publish and provider guidance makes
  this marker the new-generation default instead of asking an agent to invent
  another swirl. No new external script origin, native IPC, request route,
  filesystem access or provider tool is added. External MCP Apps do not receive
  the library.
- Keep that fixed literal in a shared pure module with an explicit package
  subpath, not duplicate desktop/backend implementations. Explicit derived
  portable HTML export includes the same library and full notice within its
  existing aggregate UTF-8 bound. It never modifies stored private source,
  digests or posters and never embeds native bootstrap, lease or credential
  authority. Preserve the source's document/doctype semantics; a bounded static
  initial fluid image outside Cafe is valid without inventing native visibility.
- At most one built-in fluid canvas per document. Bound physical canvas and
  simulation/dye dimensions, aspect ratio, all actual retained texture bytes,
  program/buffer counts, pointer count, startup/interaction frames and frame
  rate before allocation/work. Preserve the characteristic solver rather than
  replacing it with an unrelated lightweight shader. Record the final constants
  and measured fixture results before claiming qualification.
- Keep the canvas pointer-inert behind local crisp chart content and a simple
  theme-aware frosted veil. The scene stays within its chart unit, not a new
  full-page app. Real pointer decoration is passive and bounded; it cannot
  prevent scrolling, capture focus or perform a parent action.
- Read both native presentation visibility and actual document visibility.
  Permit bounded static initial poster work while hidden; pause animation
  offscreen, preserve the finite remaining animation budget, and freeze for
  reduced motion. Context loss/unsupported formats retain a readable static
  fallback. Dispose listeners, RAF, textures, framebuffers, shaders and buffers;
  resize must release exact replaced resources rather than leak old allocations.

## Security, privacy and compatibility consequences

The library is ordinary code inside the already admitted unprivileged page.
Its marker, local state and visibility hints grant no native/source/lease
authority. Adversarial received JavaScript can ignore or replace its own local
decoration; bounded helper work is not a universal GPU/RAM quota. Native
sandbox/navigation/permission denial, watchdog, exact retirement/quarantine and
the accepted macOS hard-memory exception remain independently authoritative.

The fixed library adds a bounded per-document source/compile footprint, not
per-animation-frame IPC, model-context or history traffic. No runtime/dependency
installation, lockfile change, OS policy, live session repair or source migration
is selected. Older hosts without the helper keep their independently qualified
poster/manual fallback; generation guidance must not claim they implement it.

## Implementation and evidence impact

Require pure allocation/lifecycle/cancellation tests and actual native generated
preview/viewer pixels using the supplied solver, with visible motion, hidden
pause, finite idle, reduced-motion/static/context-loss behaviour and exact GL
cleanup. Inspect synthetic captures for the intended fluid treatment rather than
using the rejected shader's pass as proof. Repeat affected wrapper, pool and
privacy checks, then all required repository gates and final forced desktop
build on unchanged source. Physical compositor, installed IME/screen-reader,
native Windows/Linux and hosted release remain separate qualification boundaries.

Update the visualization guide, package-role documentation, canonical generation
instructions and license ledger with implemented limits and evidence status.
Preserve the earlier approximation's source/evidence history in the private
execution record; do not label it the supplied engine.

The current fixed helper and its allocation/lifecycle tests are canonical for
limits. Its longest canvas side is bounded to512 physical pixels; eight
simulation/dye targets have at most16MiB logical half-float texture payload,
including format fallback. Those figures are not actual driver memory or RSS.
Initial work settles at180 frames with twelve static warm-up steps; at most six
passive trusted-pointer bursts can reach360 lifetime frames. Drawing is capped
at30fps and eight size admissions. Hidden/reduced-motion initial work is finite,
not a hidden RAF loop. Exact resource identities and deletion are covered by
instrumented browser tests; actual native driver/pixel/lifecycle qualification
is independently exercised on macOS, not inferred for another platform. Genuine
zero-size startup waits event-driven before any GL/RAF, with at most eight zero
observations and one pending observer/listener set. One-shot positive admission
removes that set; invalid dimensions or GPU failure remain terminal. This does
not renew execution or animation budgets. Unsupported initialization remains a
readable fallback, not evidence of a passed native visual gate.
