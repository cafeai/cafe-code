# Decision: exact subagent identity on ordinary provider tasks

## Context and decision

Ordinary provider task icons previously described tool type, not the worker that
performed the operation. A root Agent call can target a child, and a child's
compaction can be forwarded into the parent chat. Operation targets, labels and
control identities cannot establish the source actor. The user requests the same
subagent icon used in the roster, with no root icon.

Carry optional, bounded, typed display ownership outside raw/native tool data.
Codex obtains it only at the existing admitted notification source route, after
the repeated child/native-turn fence. Claude captures only an exact current
nonprovisional subagent task incarnation from the source's supported parent
binding; its task ID is the existing roster avatar seed, not a transcript or
spawning-tool identity. Known root may be explicit; absent legacy, ambiguous or
unqualified actor evidence remains absent. A receiver is never an actor.

Project that finite field into existing ordinary task/tool activities. The
renderer requires the same current native runtime evidence before using a child
seed and renders the shared local decorative SVG. Root and unavailable ownership
leave an empty icon slot. The seed never appears as an attribute, label, tooltip,
URL or user-visible text. This does not create another roster or native lookup.

## Boundaries and alternatives

The field grants no task-control, history-read, launch or liveness authority.
Existing current account/generation/task-incarnation checks, controls, counts,
terminal handling, workflow/roster exclusions and five-row paging remain intact.
Source ownership must not be retargeted from a later replacement task binding.
New metadata is optional for older runtimes/daemons; missing is unknown rather
than a synthesized root or child. No provider query, subscription, migration,
dependency or process/settings change is introduced.

Inferring from agent/tool names, native receiver lists, raw arguments, control
IDs or historical roster proximity could display the wrong worker. A generic
operation icon cannot satisfy identity. Copying raw provider data or exposing
native IDs is unnecessary. Explicit admitted scalar ownership preserves the
existing trust boundary while allowing reusable, recognizable local artwork.

## Qualification

Tests must cover root/child/unknown and malformed ownership, admitted versus
refused/stale routes, current versus provisional/replaced task incarnations,
complete owner carriage across starts/updates/completions, renderer generation
replacement, deterministic SVG parity and absent IDs. Preserve all original
native input, task controls, status/order/layout/scroll/focus assertions and
worker/deadline bounds. Run repository checks and forced desktop build LAST on
unchanged source before the explicitly authorized normal dev publication.

Synthetic local checks do not prove live user-session adoption, a real provider
operation, physical native process ownership or hosted release completion.
The predecessor decisions retain their accepted substance and historical evidence.
