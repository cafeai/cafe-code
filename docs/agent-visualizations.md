# Agent visualizations and MCP Apps

Status: automatic multi-view, visibility-owned generated lifetime, stable partial-scroll presentation, full-width natural inline flow, quiet controls, stronger supplied fluid and exact chat typography are implemented and locally test-qualified. Current isolated native, default, browser and copied-bridge tests pass. Mandatory final forced-build evidence is recorded separately for each resulting changeset; actual parent-compositor, installed OS and native-platform/hosted release qualification remain separate.
Last updated: 2026-10-13 13:40:12 JST (UTC+0900)

Cafe has separate paths for agent-authored pages and external MCP Apps. Both
produce immutable private artifacts and inert posters. Authenticated generated
units activate automatically when visible on a host advertising the qualified
viewport-pool capability; nearby preparation remains inert. External MCP Apps
still require explicit Run and separate consequential consent. Receiving generic
HTML is never execution authority. Ordinary HTML/SVG attachments remain inert;
Markdown, Mermaid admission and native PNG save authority are unchanged.

## Support and adoption

| Surface                                                       | Generated pages                                                                                    | External MCP Apps                                                                   |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Cafe-owned Codex session with an available desktop host       | Session-only preview/publish tools; exact native MCP completion required for a card                | Original configured MCP server only; actual native resource/catalogue APIs required |
| Cafe-owned Claude session with an available desktop host      | Session-only preview/publish tools; exact SDK tool-use/result ownership required                   | Not enabled                                                                         |
| Grok and other provider paths                                 | Not advertised or enabled without qualified native server/tool provenance                          | Not enabled                                                                         |
| Browser, remote environment or backend without a desktop host | Authenticated historical poster/source access; no borrowed local execution or runtime installation | Historical inspection only; no local viewer or provider-action parity               |

Grok's current ACP title/unknown metadata cannot establish the native MCP server
and tool. Cafe does not infer root/child provenance from it. Codex protocol types
also do not prove the configured native runtime supports Apps calls: unsupported
operations fail closed, without global-server/account fallback. Account-hosted
Apps targets are not enabled.

Native hosting reuses the existing pinned Cafe Electron application. Each
Windows/Linux/macOS host still needs its own process/watchdog/retirement and
keyboard/IME/accessibility qualification; mocked platform policies or local
browser cases do not qualify another OS. Full repository checks, final forced
desktop build and applicable hosted Quality/artifact/AppImage jobs remain release
gates, not implications of source integration.

No new runtime, browser, helper, VM, package installation, OS service or OS-policy
change is introduced. Production launches no separate application or Dock entry.
Only the opt-in synthetic native fixture launches an isolated Electron application
with its Dock entry hidden. Existing provider work receives new tools through
normal rebuilt-runtime startup/resume, not interruption or live-session repair.

## Session tools and native admission

[`visualizations/mcp.ts`](../apps/server/src/visualizations/mcp.ts) exposes only
`preview_visualization` and `publish_visualization`. Preview returns a bounded
image and diagnostics to the producer without publishing a card. Publish captures
a poster and creates an immutable revision. Neither a screenshot nor schema-valid
JSON authorizes execution or publication of another document.

Input accepts exact source, bounded title, appearance, optional viewport, request
UUID and opaque aliases for committed raster attachments. It has no chat,
account, native-session, server, path, destination or network selector. Actual
UTF-8 source bytes are bounded; unpaired UTF-16 surrogates and unknown properties,
including nested ones, are refused. Raster URLs use `asset/<logical-id>`; file
paths and arbitrary URLs do not become attachment capabilities.

[`sessionRuntime.ts`](../apps/server/src/visualizations/sessionRuntime.ts) owns a
distinct session-only MCP audience and private connection file, using the current
executable, structured argv and standalone `visualization-mcp-bridge.mjs`. It does
not edit provider profiles, approval policy or native permissions. Tokens are not
passed in URLs, argv, environment, renderer state or normal logs. Candidate
sessions can discover tools, but operations require exact generation activation.
Trusted conditional guidance preserves Build/Plan and never advertises absent
tools.

Both tools and the supported provider instruction channels share one canonical
embed-first authoring guide. It asks for fluid, compact chart/KPI/table content
that feels part of the conversation, not a second application header, logo,
navigation, hero or outer dashboard panel. Content headings and interactive
controls remain appropriate. Use the host's theme variables and interface scale,
wrap or stack at narrow widths, and keep one document scroll owner. Taller
dashboards use the host's explicit expansion rather than parent access or a
self-selected fullscreen mode.

Visual polish uses vivid data marks and highlights with the current host chart
palette, including cyan/blue/violet/magenta cues where the theme permits. Keep
series distinguishable with labels or patterns and readable light/dark contrast.
Low-opacity decorative gradients, scrims and luminous edges belong behind the
content; they should not wash out chart colours. Entrance, selection and hover
motion is the generation default: brief finite chart entrances and
interaction/hover/selection transitions while active and visible, rather than a
perpetual chart loop.

Generated charts use the same offline DM Sans variable font and sans fallback
chain as the main chat, including ordinary HTML/SVG labels and controls. Semantic
code and raw diagnostic details remain monospace. Four fixed normal/italic
Latin/Latin-ext faces are bundled from the existing pinned main-chat font; glyphs
not covered by them, including Japanese/Korean, retain the same system fallback.
The isolated preload loads only these fixed binary faces before private source,
without fetching a font or widening `font-src 'none'`. Fixed generated-only native
family styling preserves authored sizes/weights and can override explicit axis
families. External MCP Apps do not receive these fonts or style rules.
The isolated macOS font replay qualifies actual loading and full/narrow layout;
final integrated and other native-platform checks remain separate. Declaring a
font family alone is not evidence that the font loaded. Canvas
authors must await font readiness and use the computed font for measurement and
drawing; CSS cannot universally replace text already drawn by arbitrary Canvas
or WebGL code. No stored source or drawing API is rewritten. See the
[chat-typography decision](decisions/agent-visualization-chat-typography.md).

Ordinary [inline assistant images](inline-images.md) remain a separate, inert
message feature. Their authenticated metadata reserves the image aspect ratio
while bytes load, without changing a neighboring chart's native lease or the
reader's timeline scroll ownership. Charts may fill the available conversation
width while prose and inline images retain their own readable width. Opening
the ordinary image preview is an unrelated dialog and retires native charts;
closing it cannot revive a retired chart generation.
This does not grant images active HTML execution or chart-private inspection
semantics.
Stable Markdown paragraph/image component identities preserve decoded images
through same-owner workspace metadata, theme and preview-callback rerenders.
An actual owner/source change still cancels transfers and releases old image
object URLs through the existing exact-tuple image lifecycle; presentation
stability is not an authorization or persistent image-cache shortcut.

The user-selected fluid treatment reuses the actual supplied WebGL fluid solver,
shaders, shading, electric cyan-to-blue-to-violet-to-magenta palette and virtual
orbit. It is not a substitute polar-wave shader or a request for an agent to
approximate the effect. The fixed library is bundled into generated documents
only, under the existing inline-script policy; it grants no native API or new
network origin. New-generation guidance adds exactly one
`<canvas data-cafe-fluid aria-hidden="true"></canvas>` inside a relatively
positioned chart unit. The canvas stays absolute and pointer-inert behind a
local translucent theme-aware frosted veil, with crisp vivid charts/text above.
There is no copied hero, photo, form, navigation, parent-backdrop sampling or
screenshot access. Source without the marker starts no built-in fluid work;
external MCP Apps do not receive the helper. Older hosts without it retain
their independently qualified poster/manual fallback.

The adapted helper retains the supplied fluid equations and characteristic
motion with fixed canvas/texture/resize work, coalesced passive pointer input,
offscreen pausing and explicit GL resource teardown. The
[visibility-owned decision](decisions/agent-visualization-visible-lifetime.md)
removes the generated viewer's five-minute lifetime and the helper's cumulative
frame cutoff. One RAF remains capped at30fps; bounded modular phase and
saturating diagnostic counters avoid lifetime-growing state. Final display
colour gain is2.0 following the user's stronger-visibility refinement, without
changing solver equations or adding GL resources. Static fallback alpha is.24.
New-generation guidance uses canvasopacity.8–1 and a local60–70% veil to avoid
burying the decoration while keeping foreground contrast crisp. Existing
received source styles are not rewritten. Current visual qualification is pending.
The eight admitted physical-size changes and other resource fences remain.
Unused disabled-bloom/noise allocations are removed. Static
fallback covers reduced motion, unavailable formats/WebGL and context loss.
The helper is integrated with focused shader-provenance, allocation and cleanup
tests. Actual macOS native preview/viewer captures show the supplied fluid, and
the isolated four-viewer/preview, animation, visibility, context-loss and
retirement checks pass. Full repository and native Windows/Linux/hosted
qualification remain separate; earlier approximate-shader passes are not proof
of this look.
The [fluid-background decision](decisions/agent-visualization-fluid-background.md)
records that distinction and the supplied implementation identity. Its full MIT
notice is preserved in [NOTICE.md](../NOTICE.md) and the embedded helper.
The canonical fixed source lives in the shared
[`visualizationFluidRuntime.ts`](../packages/shared/src/visualizationFluidRuntime.ts)
module, not a runtime read of a user's local template.

Its canonical fixed source bounds canvas, simulation/dye textures, coalesced
interaction work, frame rate and resize admissions. Resource tests count exact
GL objects and logical texture payload; these are not physical GPU-memory or
process-RSS measurements. Only admitted visible live charts animate; hidden
charts, reduced motion and portable/static previews retain a bounded last frame.
Saved history is not an automatically running animation loop.
Static reduced-motion content still needs a correctly sized raster. An actual
visible physical-size change may rebuild the same admitted targets and perform
twelve bounded warm-up steps without RAF or polling, with saturating diagnostic
counters rather than a lifetime frame allowance. Duplicate sizes and later hidden events
do no work; initial hidden/export warm-up stays twelve steps. Existing finite
resize, texture, program and canvas limits remain authoritative.
An initially zero-sized native canvas waits for real layout with no GL or RAF;
at most eight zero-layout observations are admitted. The single pending
observer/listener set is removed before one-shot initialization or teardown.
Positive invalid dimensions and GPU failures remain terminal, not blind retries.

Bounded helper work is not an enforced quota for arbitrary received JavaScript,
a hard GPU-memory guarantee or supervision of shared native GPU services.
Avoid unbounded chart loops, remote dependencies and scroll hijacking. The host supplies
`html[data-cafe-reduced-motion=true]` as well as its finite presentation context;
authored styles should react to that flag and native reduced-motion media changes.
The marker is the generation default; the library supplies the actual effect,
not a model-authored recreation. Instructions are not a sanitizer or guarantee
that arbitrary agent-authored HTML follows the layout. Existing immutable
source and posters are not rewritten;
newly generated revisions can adopt the improved design guidance.

Native-view visibility is not reliably the browser's `document.hidden`. The
trusted wrapper starts with `html[data-cafe-visible=false]` before source code.
Generated logical viewport visibility is separate from native paint visibility:
after qualified positive geometry, a tiny crop or menu can hide pixels without
replaying the logical-visible entrance. The separate
`data-cafe-presentation-visible` scalar and `cafe-presentation-visibility-changed`
event pause/resume the bundled helper; native input/focus/capture remain refused
while paint is hidden. Actual logical changes emit `cafe-visibility-changed` with
`{visible:boolean}`. Apps and preview retain their original visibility semantics.
Animation should read initial values and recheck them and `document.hidden`
before every frame. A hidden private preview may draw one static initial poster;
motion requires logical and paint visibility plus a nonhidden document.
This is cooperative authoring information,
not lease or permission authority: source can ignore or alter its own local
presentation data, while native admission, masking, retirement and watchdogs
remain independently enforced.

Producer authority binds chat, provider instance, session generation, runtime
generation, token digest and server name. Activation compares the predecessor
under the SQL writer; old disposal cannot revoke a replacement. Store operations
recheck current authority under the writer. Internal native Apps operations use
`requireActiveSession` before and after asynchronous native I/O. Replacement,
retirement or hard deletion revokes producer/action authority; renderer/backend
reconnect alone does not prove a surviving detached owner has retired.

Publication returns an **unclaimed**, private per-invocation receipt. Request UUID
and exact input digest deduplicate immutable bytes, while every invocation gets a
fresh 256-bit proof. Only the owning adapter can claim it against the actual
successful completed native call: bound server/tool/generation, original input
digest, native item/turn and root/child ownership must match. Proof digest and
unique native-call binding settle transactionally. Arrival order, titles,
model-authored IDs and copied/stale/incomplete receipts cannot admit a card.

Ordinary streams carry compact references and safe attribution only. Source,
proofs, assets and native payloads are filtered before Cafe native logs, daemon
replay, canonical mapping and child projection. The upstream provider necessarily
receives source in its tool request and may retain it in its own history; Cafe
cannot erase or promise privacy of provider-owned transcripts.

Malformed Claude parent frames mask their own unowned results without hiding
later valid ordinary tool output; an uncorrelatable genuinely private tool or
exhausted private identity table remains fail-closed. Codex rejected-schema
diagnostics retain fixed metadata/auth/framing classifications, never received
causes or arbitrary rejected method text.

## Private storage and long history

[`store.ts`](../apps/server/src/visualizations/store.ts) and
[migration 096](../apps/server/src/persistence/Migrations/096_GeneratedVisualizations.ts)
keep source, original input JSON, assets, diagnostics and poster bytes in dedicated
private SQLite rows, outside ordinary event journals. Domain-bound digests commit
exact content/manifests. Ready rows cannot be edited or revived through a
pending-state transition. Hashes prove integrity, not authorization.

Raster imports require an existing same-chat attachment commitment, held
no-follow original-file reads, file/parent identity and private-mode checks where
applicable, actual byte bounds and SHA-256 verification. Cross-chat IDs, unsafe
namespaces, replaced/growing originals and changed commitments are refused.
Snapshots survive later original-file movement/deletion. Native image admission
also bounds dimensions/pixels and decodes/re-encodes the raster. Imported SVG is
not a raster exemption; agent-authored inline SVG belongs to the code budget.

Durable compact history is independent of the 500-activity tail. Bounded pages
carry canonical message/turn anchors, attribution and immutable refs. Fork copies
deliberate historical references, never producer tokens or Apps action authority.
Revert prunes exact discarded anchors; hard deletion releases only that chat's
references. Retained forks prevent removal of their bytes. Last-orphan retirement
and cleanup are indexed bounded batches, not full-history/token-path scans.

The renderer retains at most 1,000 compact entries, not every stored row. Explicit
Load older gestures slide that window through older history; new activity does
not replace an older review window. Return to latest requests a fresh current
window. There is one in-flight page and at most one trailing current refresh,
without automatic history scans. Exact originating-call anchors distinguish
history/card/viewer identity even when publication deduplicates immutable bytes;
source and poster caches remain content/revision keyed. Retrying a failed page
preserves its mode/cursor rather than silently returning to live history.

Claimed history is not silently age-evicted. Quota exhaustion refuses new writes,
not retained source. Unclaimed receipts and failed pending captures have finite
recovery lifetimes. Failed capture keeps pending source private but produces no
success receipt/card/claimed-details read. This version exposes fixed failure
counts/reason, not a separate failed-source inspection UI.

## Seamless viewport units and their limits

Generated units report only bounded natural content height through the isolated
native preload, never raw DOM or source. Exact document/nonce/frame/lease and
monotonic sequence checks precede host admission. Coalesced measurements reserve
inline card height in the conversation so natural chart content uses the chat's
scroll flow instead of a second root scrollbar. Fixed/absolute decoration does
not inflate that measurement. The finite inline limit and expanded viewport
remain unchanged; genuinely oversized content is explicitly constrained, not
silently hidden. Viewport-dependent or deliberately nested-scroll authored
source cannot be universally reformatted by this host contract. External Apps
retain their separate sizing/permission semantics. Focused layout/motion tests
qualify these isolated boundaries; full repository and release checks remain
separate requirements.

Committed callback forwarding keeps ordinary timeline rerenders from retiring a
same-identity chart. A wholly never-attempted registration can be cleaned up and
replayed during development's StrictMode startup checks without inventing a
terminal native epoch. Once a request, preparation or native admission begins,
cleanup remains immediate and terminal; Stop, expiry, owner loss and uncertain
acknowledgement never become automatic retries.

Inside the real virtualized timeline, generated execution waits for that exact
list's public initial-load completion. Inert poster loading and private inspection
do not wait. Removing an empty/loading list and later mounting a new one requires
a new completion signal, even in the same chat. Streamed rows, theme and natural
height changes of the same present list never reset readiness. This avoids native
input racing an unfinished startup scroll without changing general tail/review
anchoring, adding a timer or renewing an execution epoch.
Restored stopped/waiting snapshots notify only their exact keyed subscribers
after the new registration installs its binding and mount. This wakes a card
that was already subscribed while readiness was held; it does not issue native
work, clear a terminal epoch or renew a lease.

Timeline cards retain an inert poster until the exact native visible commit;
private Source/Details remain explicit authenticated disclosures. Active ownership
lives outside recycled timeline rows. A generated chart, table or KPI unit can
prepare an exact revision's one-use ticket shortly before entering view, then
activate automatically in its actual clipped viewport. Multiple visible units
can run together. Trusted renderer-to-main IPC carries only the opaque ticket,
bounds and appearance, never source, paths or an arbitrary executable URL.

Automatic admission requires the explicit native pool capability and its bounded
capacity observation. An older or unavailable host does not gain that authority
from method names or HTML alone; it retains posters and only its independently
qualified manual fallback. External Apps remain manual. Native capacity is a
scheduling hint, not ownership or retirement evidence.

Each mounted unit binds an opaque pane plus its authenticated invocation and
revision. Visible inactive split panes are eligible; focus changes scheduling
priority, not document authority. Closing one pane cannot retire a sibling that
shows the same chat. Stable keyed subscriptions and finite mounted/epoch ledgers
avoid scanning history on token updates. More units than the native capacity
remain posters while waiting for a capacity event, not a polling/retry loop.

Stop, applicable expiration, refusal and indeterminate acknowledgement end that
visibility epoch. Current hosts explicitly advertise generated visibility-owned
lifetime: null expiry means no running-chart clock, not an infinite timestamp or
renewed lease. Legacy hosts and external Apps retain their finite policy. Row
recycling, theme, resize, modal changes and expansion never renew those finite
budgets or revive terminal authority. An observed offscreen-to-visible visit or
explicit Restart can request a fresh epoch. A full epoch ledger fails closed
instead of evicting old Stop decisions. Failed or cancelled preparation discards
only its exact unused ticket; it never revokes every viewer of the same revision.

Public history reads, private disclosures, and active viewers bind the exact
registered environment connection and its authenticated transport generation.
The renderer's API adapter is stable only for that connection's lifetime; a new
connection gets a new adapter even if it reuses the same RPC client. A weak
connection-keyed cache avoids retaining retired clients. Reconnect, replacement,
or loss of the owner role still revokes in-flight private/native responses; the
cache does not bypass those checks or restore a viewer automatically. Revocation
is one-way for each observer: restoring a role or reusing the same connection
timestamp cannot revive an old private response, consent, or native open reply.
A fresh disclosure requires a fresh user action; generated execution requires a
fresh exact-owner admission under the visibility-epoch rules above.

[`DesktopVisualizationHost.ts`](../apps/desktop/src/visualizations/DesktopVisualizationHost.ts)
owns four app-wide viewer reservations plus one separate preview lane and two
waiting previews. At most one manually activated external App occupies one of
those four viewer slots, not an extra fifth viewer. Starting, retiring and
uncertain viewers still occupy reservations. A fresh nonpersistent Session and sandboxed context-isolated
`WebContentsView` have Node disabled, no ordinary Cafe preload, credentials or
management bridge. Before private source, an inert bootstrap must demonstrate
actual exclusive renderer identity distinct from trusted Cafe views. Unknown or
shared ownership is refused; a matching PID is not termination authority.

The isolated bootstrap loads one dedicated top-frame. Native session gates deny
source-controlled frames, workers, navigation, windows, downloads, permissions,
filesystem/backend URLs and arbitrary network requests. Header CSP is defense in
depth, not a quota. Active pages receive finite presentation/protocol channels
only. Generated pages are offline. External Apps get separately approved
originating-server operations, not a generic network or MCP proxy.

The watchdog runs in trusted Electron main, outside the page event loop. Missing
heartbeat/deadline revokes actions and retires the exact surface. Observed renderer
disappearance plus destruction is required before releasing the exact slot;
uncertainty quarantines new admission across the whole pool while healthy siblings
can still retire. This does **not** supervise a stalled
main process, native browser service, kernel or whole-system pressure. The user
explicitly accepts **no hard total-memory cap on macOS**. No Job/cgroup/VM resource
enforcement is installed or universal CPU/RAM envelope claimed. Chromium
sandboxing and bounded trusted copies/messages remain independent controls.

Viewer startup remains hidden until its exact trusted lease commits current
geometry and visibility. Generated visibility-owned admission has a fixed
20-second first-presentation deadline beginning at native record admission,
independent of timer scheduling; delayed acknowledgements do not renew it.
Once qualified presentation commits, healthy visible execution has no clock
limit. Revocation during capability, ticket or open acknowledgement cannot reveal
the stale document; consent resume cannot expose an uncommitted view.
Expansion retains the selected native document. Other views yield before its
overlay appears, and old inline pixels hide during a finite native presentation
transition. A yielded generated sibling may resume only with a one-use
native-owned continuation with a finite spending deadline and the original
document's lifetime policy, never a renewed external-App allowance. Arbitrary DOM
state does not survive retirement; linked controls can remain together in one
document. Approvals/modal UI hide/yield the views. Stop, owner loss, route/window
changes, applicable deadline or wholly lost visibility retire execution.
CSS hiding is not indefinite execution permission.
Inline layout reserves the same bounded height for passive and active content
from the actual chat viewport, not the whole desktop. The surrounding panel is
minimal so charts can flow with the conversation. Generated rows use the full
available chat column; ordinary prose and Apps retain their existing reading
width. Natural height grows into chat flow within finite viewport limits rather
than concealing overflow or stretching chart glyphs. Expansion fills the usable
viewport while retaining host actions and native titlebar clearance.

On visibility-owned hosts, generated title/provenance/time, lifecycle actions,
PNG/HTML export and explicit private source/JSON inspection live under the
shared accessible “…” menu. Its trigger is outside native pixels and revealed
on hover/focus, with touch access. Menu/details overlays hide exact generated
presentation before opening and hold that reservation through portal exit.
Private bytes clear immediately on close or ownership loss, independently of
the presentation reservation. Legacy hosts keep their truthful finite controls;
external Apps retain explicit activation and consent rather than borrowing this
generated-only policy.

Automatic generated execution must not take composer focus. Native pointer
interaction, deliberate Enter/Space on the focused chart anchor or explicit
expansion may focus the exact chart; source-driven
autofocus is not a user gesture. A narrow trusted native-wheel handoff scrolls
only that chart's owning timeline when the guest cannot scroll further. Local
scrollable content and modified chart gestures remain local. This is not a
generic guest-selected parent action, synthetic browser input or permission to
activate an application. Manual Apps keep their separate input semantics.

The native geometry contract separates the full owner-page CSS viewport from
its visible intersection with the card's clipping ancestors and window. Main
maps those values using the exact owner WebContents zoom, independently of
display DPR, and positions the same full-size document inside a native clipping
parent. Partial chat scrolling changes the crop and offset, not responsive page
layout or document state. The existing native viewport/capture limits are not
enlarged. Unknown geometry retires execution. An independently qualified positive
generated slice below the native mask's32-DIP minimum hides both native layers
while retaining the exact document and watchdog; it never installs unsafe mask
geometry or permits input/capture. Fresh qualified geometry can restore that
same live document. Whole offscreen or owner loss still retires it. Explicit
generated menu overlays use the same presentation-only hiding policy; arbitrary
JavaScript is not forcibly paused by a cooperative hint. The mask uses a tiny
positive corner radius and an explicitly materialized native compositor layer:
an ordinary DOM overflow rule, zero-radius view or guest screenshot is not proof
of native clipping. Native bounds/state/capture qualification remains distinct
from an actual on-screen compositor observation after normal user-owned adoption.
State survives only in the same admitted live document; reopening gets a fresh
generation. Same-value generated visibility/presentation notifications are
idempotent, so ordinary partial scrolling does not repeatedly trigger received
animation listeners. Paint-only tiny-crop/menu transitions retain logical
visibility, while actual browser/logical transitions remain observable: arbitrary
older source can react to those transitions. New generation
guidance requires entrance once per document and finite animated data changes,
not scroll/resize replay. Stored source is never rewritten by that guidance.
Semantic generated tooltips use theme-backed surface/foreground/border values.
The opt-in macOS arm64 fixture verifies real focus, pointer/character
input, Unicode committed text, keyboard selection and Chromium's semantic
accessibility tree. Committed text is not installed IME composition/cancellation;
the Chromium tree is not an OS screen-reader smoke test. Those manual native
checks and other platforms remain distinct, not inferred from pixels or mocks.

Saved posters represent their immutable capture, not arbitrary current state.
Explicit appearance controls publication capture; `auto` currently uses a dark
baseline. Trusted live appearance can differ. PNG actions are labelled saved
poster unless an exact current-state capture has been established.

## External Apps and one-use consent

[`mcpApps/owner.ts`](../apps/server/src/mcpApps/owner.ts) captures only actual
successful completed Codex MCP calls with exact configured server/tool/native
owner and a catalogue-matching `ui://` resource. Expected MIME is
`text/html;profile=mcp-app`. Private snapshots include exact original input/result,
resource metadata and immutable native witness. Missing, oversized and unsupported
resources do not become successful Apps artifacts.

Private poster capture supplies only the exact bounded original input/result
tuple through a preview-only initialization replay. This data-only lane refuses
tool/resource actions, model-context changes, chat messages, links and display-mode
requests. It is absent from stored viewer documents, viewer preparation and
renderer IPC; active viewers use the separately authenticated protocol broker.

The supported Apps protocol is `2026-01-26`. Initialization delivers the exact
captured input/result once and in order for each fresh document. Dedicated
isolated-bootstrap transport is not the ordinary Cafe preload. Unknown/draft
methods are rejected. Unsupported downloads, native permissions and arbitrary
remote resources are not advertised as generic host capabilities.

[`mcpApps/service.ts`](../apps/server/src/mcpApps/service.ts) requires the owned
immutable revision, current native account/session/server, and actual host
inspection matching ticket, lease and document generation. Consequential actions
need separate one-use consent consumed before I/O. Catalogue, app tool visibility,
argument schema, resource scope and exact owner are re-observed after asynchronous
reads and immediately before execution. `readOnlyHint` is advisory, not consent.
Account/session A→B→A, old documents and lost ACKs cannot replay authority.

`tools/call` and `resources/read` stay on the originating server. `ui/message`
requires approval and normal durable chat submission. `ui/update-model-context`
replaces bounded untrusted next-turn context, not system/developer instructions;
it starts no inference. Links need exact credential-free safe-destination consent.
Provider stop/replacement removes actions, not historical poster/source. Reopening
does not restart a provider. Consent yields the view for a fixed finite interval:
duplicate suspension cannot renew it or the document's absolute lease. Fullscreen
retains the same document where supported; native approvals stay outside its
authority.

## Explicit inspection and HTML export

Owner-only Source/Details bind and echo **thread, artifact and revision**.
Integrity/tombstones and authentication are rechecked around asynchronous work.
Bounded raw JSON/source are escaped received data behind disclosure, never
collapsed summaries, automatic logs or inference context. Schemas do not prove
user-authored text contains no credentials: deliberate inspection can reveal
private material authored into the request/document.

Generated HTML export requires executable-content disclosure. The
[static rewriter](../apps/server/src/visualizations/offlineHtml.ts) embeds admitted
manifest raster bytes only when a **complete literal URL attribute** is exactly
`asset/<logical-id>` in `src`, `href` or `poster`. It does not rewrite substrings,
external-URL suffixes, comments, raw script/style text or ordinary labels. CSS
URLs, `srcset`, JavaScript/dynamic URLs, encoded aliases and other dependencies
must already be self-contained. This is static declared-asset export, not universal
HTML portability. Apps are not exported as portable live server authority.

The explicit derived generated export also includes the same bounded fluid
library and MIT notice so a `data-cafe-fluid` canvas retains its initial fluid
image outside Cafe. That copy counts against the existing total UTF-8 export
bound; stored Source/Details remain the exact original immutable source. No
native visibility, lease, transport or permission bootstrap is exported.

The same explicit derived export includes the fixed offline chat font faces,
family styling and their complete SIL Open Font License. Their actual encoded
bytes are reserved together with any fluid helper before raster expansion within
the existing total export bound. Original Source/Details bytes stay immutable.
There is no exported font fetch, native transport, lease or new Cafe capability.

Exported HTML can run JavaScript and network requests outside Cafe and has no
Cafe native-denial/watchdog policy. No Cafe token, viewer ticket, management
capability, provider credential or local file path is intentionally embedded.
Explicit download is not arbitrary filesystem-write/provider authority. Saved
poster PNG actions retain the existing validated, requesting-document-bound
native save policy.

Logical SQL quotas do not bound physical SQLite/WAL size or workstation RAM.
Base64/JSON/capture/decoder copies have separate finite transport limits, not
per-animation-frame history traffic. Direct private MCP HTTP counts actual bytes
before assembly/SDK parsing, with independent chunk and body-time fences.
Generated MCP responses retain their four-operation allowance through Node's
actual finish/close, not merely SDK response creation or source-stream exhaustion.
The delivery guard starts at response handoff, never renews on bytes and does not
shorten or extend the separate 20-second native preview budget. Slow or disconnected
readers cannot release an allowance while Node still retains their outgoing data.
Capture admits display scale and actual physical dimensions before accepting
native output; owner/document/display identity is rechecked around capture.
Physical RGBA (at most 51.2 MB), normalized RGBA (at most 12.8 MB) and finite
encoded/transport buffers are separate allocations, not a total-memory cap.
The private owner transport's larger outer allowance accounts only for JSON
escaping. It never enlarges App protocol, replay or page limits and does not
change ordinary daemon RPC or scheduling transport policy.
Poster-first history and bounded pagination avoid source hydration on every token.
No speed/memory improvement percentage is claimed without measurements.

Desktop debug exposes fixed lifecycle/queue/byte/capture/watchdog/retirement
counts/states, pool viewer/preview/preparation/native-work/continuation counts,
and bounded viewport/clip dimensions, owner zoom and geometry
outcome only, never page coordinates or a retained native view. Fixed
`nativeVisibility`, `visibilityHintSent` and `visibilityCommitted` fields
distinguish the native hidden/visible/unknown observation from the last sent
cooperative presentation hint and the first trusted visibility commit. A sent
hint is not evidence that arbitrary page code paused, and no per-frame page
inspection or RAF counter is added. Backend
`/api/visualizations/debug?threadId=<id>` requires
explicit Debug mode, observed loopback, no HTTPS proxy marker and fresh owner
authentication. It returns pending/ready/failed capture counts and fixed
`capture-unavailable`, plus separately labelled local-process Apps owner/capture/
context/refusal counts. Those process-local counts are not exact-thread or
whole-daemon health/authority evidence. Neither path returns source, raw JSON,
tokens, native IDs, paths, image
buffers or exception causes. Debug availability cannot grant pending-source read
authority.

Capacity observation in the ordinary sandboxed desktop preload uses browser
WebCrypto, not an unavailable Node crypto import. Each first registration gets a
fresh cryptographic UUID; unavailable randomness refuses observation before
retaining a listener. Independent duplicate cleanup, exact native owner checks
and monotonic observation epochs remain intact. The existing emitted-preload
build guard still rejects Node crypto and other unavailable modules. A
successful unit check is not a successful emitted desktop build.

native-policy fixtures qualify their isolated boundaries only. They do not prove
live provider support, OS permission delivery, native input/accessibility, hostile
